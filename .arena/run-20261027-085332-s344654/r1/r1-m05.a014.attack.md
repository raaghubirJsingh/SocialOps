ATTACK 1 [MAJOR] Middle phrase drifts from software reliability into testing
Where: "tests catch the bug before launch"
Problem: The task requires the haiku to be about software reliability. This phrase describes testing / quality-assurance activity (finding bugs before shipping), which is a distinct subject from reliability. The framing "before launch" reinforces the drift: reliability is fundamentally an operational, post-deployment property, but this line anchors the haiku in pre-release testing. With the middle line on testing rather than reliability, the requirement "Subject: software reliability" is only partially met — a reader looking for a haiku about software reliability gets one about the testing process.

ATTACK 2 [MINOR] Opening phrase asserts a false absolute about software reliability
Where: "Code runs without fail"
Problem: Software reliability is probabilistic; real production software always carries some failure probability (e.g., "99.99% uptime", never 100%). Claiming that code "runs without fail" is factually incorrect about the subject. The haiku opens with a claim about software reliability that no real system can satisfy, so the subject is introduced with an inaccurate statement.
